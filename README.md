# harness-ios
**iOS 앱 개발을 위한 Claude Code 에이전트 팀 하네스 템플릿**입니다.
**기술 리서치, 기능 구현, 단위 테스트, QA, 개발 문서 작성, 커밋 메시지 작성, PR 작성을 담당하는 7개의 에이전트**와 이를 **조율하고 관리하는 오케스트레이터**로 구성되어 있습니다.

- 플러그인/마켓플레이스가 아니라, 그대로 복사해서 사용하는 스킬/에이전트 번들(템플릿)입니다.

## 왜 템플릿인가요?
이 하네스는 특정 프로젝트에 그대로 적용하는 완성형 솔루션이라기보다 **사용자가 자신의 프로젝트 구조와 개발 방식에 맞게 수정하고 확장할 수 있는 템플릿**을 목표로 합니다.

따라서 프로젝트의 아키텍처, 브랜치 전략, 코딩 스타일, 테스트 방식, 문서화 수준 등에 맞춰 **에이전트의 역할과 프롬프트, 워크플로를 자유롭게 커스터마이징**할 수 있습니다.

즉, **정해진 정답을 제공하기보다 각자의 개발 환경에 맞는 에이전트 팀을 구성할 수 있도록 기본 골격을 제공하는 것**이 이 템플릿의 목적입니다.

## 구성

```
agents/ - 7개 에이전트 정의 (ios-researcher, ios-developer, ios-unit-tester, ios-qa, ios-doc-writer, git-commit-writer, pr-writer)
skills/ - 각 에이전트가 쓰는 전문 스킬 + ios-dev-orchestrator(조율 스킬)
templates/ - PROJECT_CONVENTIONS.md (설치 후 사용 프로젝트의 CLAUDE.md에 채워넣는 템플릿)
```

- `ios-researcher`는 **`context7` MCP 서버를 사용**합니다. 설치 환경에 `context7` MCP가 연결되어 있어야 라이브러리 문서를 조회할 수 있습니다. 없어도 웹 검색으로는 대체 동작하지만, 최신 라이브러리 문서 조회 품질이 떨어질 수 있습니다.
- 이 하네스 템플릿은 **특정 아키텍처(MVVM, TCA, 클린 아키텍처)나 UI프레임워크(SwiftUI/UIKit)에 종속되지 않습니다.** 실제 스택은 사용 프로젝트의 'CLAUDE.md`에 적힌 컨벤션을 최우선으로 따르도록 설계했습니다.

## 설치
** 전역 설치 (모든 프로젝트에서 사용) **
```bash
mkdir -p ~/.claude/agents ~/.claude/skills
cp -R agents/* ~/.claude/agents/
cp -R skills/* ~/.claude/skills/
```

**특정 프로젝트에만 설치**

```bash
mkdir -p .claude/agents .claude/skills
cp -R {이 저장소 경로}/agents/* .claude/agents/
cp -R {이 저장소 경로}/skills/* .claude/skills/
```

- 명령어에 문제가 있다면, 해당 프로젝트의 .claude/agents, .claude/skills 경로에 파일을 붙여넣어도 동작합니다.
- 설치 후 별도 재시작 없이 다음 세션 또는 다음 새 대화부터 스킬과 에이전트가 인식 됩니다.

## 설치 후 해야 할 일 — 프로젝트 컨벤션 작성
`templates/PROJECT_CONVENTIONS.md`를 열어 이 프로젝트의 실제 스택(UI 프레임워크, 아키텍처 패턴, 모듈화 방식, DI 방식, 테스트 프레임워크 등)을 채운 뒤, 그 내용을 프로젝트 루트 `CLAUDE.md`의 `## 프로젝트 컨벤션` 섹션으로 붙여넣습니다.

- 컨벤션을 채우지 않으면 에이전트가 기존 코드를 탐색해 추론하거나, 완전 신규 프로젝트에서는 SwiftUI+MVVM을 기본값으로 쓰고 그 가정을 결과에 명시합니다.

## 사용
별도 트리거 문구 없이 "기능 구현해줘", "QA 해줘", "단위테스트 작성해줘", "커밋 메시지 써줘", "PR 만들어줘" 같은 요청만으로 `ios-dev-orchestrator`가 자동으로 필요한 에이전트를 라우팅합니다.
